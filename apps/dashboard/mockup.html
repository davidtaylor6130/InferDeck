Handoff notes (for implementation · not part of the UI)

  1. Runtime now → resident models. Replace the single loadedModel with the ModelInfo[] resident list (already in the models payload). Per model: slot pips — used = filled green, free = dashed outline — plus busy/total and VRAM used.
  2. Per-slot live rows. Running requests grouped under their model/slot: client key, PP (promptTokensPerSecond), TPS (tokensPerSecond), elapsed. This is the live per-slot view that replaces the flat active-request list on Home; the Requests page stays as-is.
  3. Waiting queue. Use status.queue.requests[] (already exists: id, model, priority, position, queuedMs, remainingMs) plus a one-line reason (slots busy / not resident). Data gap: queue entries need the auth principal — carry the resolved API key (name + priority) into each queue entry at admission.
  4. API key chips. Requests already carry principalClass; expose key name + priority (and prefix on expand) from ApiKeyRecord. Dashed chip = public / no key.
  5. Sidebar. Per-section accent (LLM blue, Dictation amber, Image violet, Music orange), item count on the header, collapse state persisted via the existing sidebarPreferences, active item gets a 2px accent left bar. Top-level links stay neutral.
  6. Account card, bottom-left. User icon + account name + role + API-key count + menu (Account / API keys / Log out), replacing the bare version block (version stays as a small line beneath). Feeds the existing DashboardAccess state.
  7. App shell is viewport-locked. The page must NOT scroll — the app shell is h-screen overflow-hidden and only main scrolls (overflow-y-auto). This keeps the sidebar (and its bottom-left account card) pinned to the viewport, not the page height. The top bar stays shrink-0 (no sticky needed inside the fixed shell).
  8. Live stats live in the right column. The whole-machine (aggregate) GPU / VRAM / temp / speed sparklines sit under their matching headline stat in the "Runtime now" right column — not as a separate full-width section. Each headline stat is paired with its own sparkline (GPU util under GPU, VRAM under VRAM). Per-slot detail stays in the resident-model rows only.
